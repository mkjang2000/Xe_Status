# XE Status

개인이 운영하는 서비스의 상태를 확인하고 외부에 공개하는 작은 상태 페이지입니다. React + Vite, Fastify, TypeScript, SQLite와 별도 검사 워커로 구성합니다.

## 시작하기

Node.js 22.12 이상과 npm이 필요합니다. Ping 검사는 Linux `ping` 실행 파일을 사용합니다.

```bash
npm ci
npm run setup
npm run dev
```

- 공개 페이지: http://localhost:5173
- 관리자: http://localhost:5173/admin
- `npm run setup`이 생성한 관리자 비밀번호로 로그인합니다. `.env`가 있으면 덮어쓰지 않습니다.
- 모니터를 등록하면 워커가 실제 검사를 시작합니다. 기본 서버나 가상의 정상 이력은 넣지 않습니다.
- 관리자 비밀번호는 관리 콘솔의 **비밀번호** 탭에서 변경합니다. 현재 비밀번호와 새 비밀번호(12~1024자), 확인 값을 입력하세요. 변경하면 모든 세션이 해제되며 새 비밀번호로 다시 로그인합니다.
- 새 비밀번호는 salt와 scrypt 해시로 DB에 저장되고 재시작 후에도 유지됩니다. 콘솔에서 변경한 이후에는 `.env`의 초기 비밀번호가 아니라 DB에 저장된 비밀번호를 사용합니다. `.env`는 서버 구동 설정으로 계속 보관하세요.

기본 API 포트 3000이 사용 중이면 `PORT=3080 API_PROXY_TARGET=http://127.0.0.1:3080 npm run dev`처럼 다른 포트로 실행할 수 있습니다. 공개 화면 주소는 그대로 `http://localhost:5173`입니다.

## 제공 기능

- Ping, HTTP/HTTPS 응답 코드, JSON 중첩 필드 조건 검사
- 주기·타임아웃·연속 실패 및 복구 기준 설정
- 정상 / 장애 / 점검 / 미확인 표시, 최근 30일 막대와 장애 이력
- 모니터 일시정지, 수동 점검 또는 종료 시각이 있는 점검
- 페이지 이름·설명·로고·파비콘·상태 색상 설정
- SMTP 장애·복구 알림, 테스트 메일, 발송 결과 확인

JSON 조건은 `database.connected`처럼 점으로 구분한 필드 경로를 사용합니다. 필드 이름에는 영문자·숫자·밑줄·하이픈을 사용할 수 있고 배열은 `items.0.status`처럼 접근합니다. 비교 값은 문자열·숫자·불리언·null을 지원하고 모든 조건을 만족해야 정상입니다. 임의 스크립트 실행은 지원하지 않습니다.

로고와 파비콘은 HTTP/HTTPS 이미지 URL로 지정하며 운영 환경에서는 HTTPS를 사용합니다. HTTP 검사는 기본 GET이며 HEAD와 POST도 지원합니다. POST 모니터는 부작용이 없는 상태 확인용 API에 사용하세요. 리디렉션은 같은 출처 내에서 최대 3회까지 지원하므로 가능하면 최종 URL을 등록하세요. 응답 본문은 최대 1MB입니다.

## 상태와 가동률

- 검사 실패: 서버 응답 시간 초과, 연결/TLS 실패, 응답 코드 또는 JSON 조건 불일치
- 미확인: 첫 검사 전, 일시정지, 검사 결과 만료, 로컬 검사 도구 누락
- 표시 상태와 메일은 연속 실패·성공 기준을 사용합니다. 개별 실패 기록은 그대로 유지합니다.
- 가동률은 `정상 시간 / (정상 시간 + 장애 시간)`입니다. 미확인 시간은 제외합니다.
- 한 검사 결과는 다음 결과 또는 설정한 한 검사 주기까지 적용합니다. 워커가 멈춘 공백을 정상으로 채우지 않습니다.
- 점검 중에도 실제 검사 결과를 가동률에 반영하고 메일 알림은 억제합니다. 점검 종료 후에도 장애면 다시 알립니다.
- 일별 이력 경계는 한국 시각(Asia/Seoul)입니다. 관측 기록이 없는 날은 회색으로 표시합니다.

## SMTP

관리자 화면에서 호스트, 포트, TLS 방식, 인증 정보, 발신자와 수신자를 저장하고 테스트 메일을 요청합니다. 워커가 발송하므로 워커가 실행 중이어야 합니다. 저장된 비밀번호는 다시 표시하지 않으며, 비밀번호 입력을 비워 두면 기존 값을 유지합니다.

TLS 연결(일반적으로 465)과 STARTTLS(일반적으로 587)를 지원하며 인증서 검증을 끄지 않습니다. 발송 오류는 제한된 횟수로 재시도하고 검사 작업은 계속됩니다. 발송 후 DB 기록 직전 프로세스가 종료되면 같은 메일이 다시 전달될 수 있습니다. 점검 전 이미 SMTP 서버가 수락한 메일은 취소할 수 없습니다. 이미 SMTP 전송이 시작된 메일은 점검 전환으로 회수할 수 없습니다.

## 운영 배포

먼저 `.env`에 `NODE_ENV=production`, `APP_ORIGIN=https://status.example.com`을 설정하고 HTTPS 역방향 프록시를 준비합니다. 프로덕션에서는 HTTPS `APP_ORIGIN`이 없으면 서버가 시작하지 않습니다.

```bash
npm run build
# 별도 터미널 또는 프로세스 관리자로 각각 실행
npm start
npm run worker
```

공개 페이지는 `/`, 관리자 화면은 `/admin`입니다. API와 화면은 설정한 같은 origin으로 제공해야 하며 관리자는 HTTPS 주소에서 로그인합니다. 프로덕션 세션 쿠키는 HTTPS에서만 전달됩니다. 개발용 Vite 서버를 운영에 사용하지 않습니다.

Docker Compose를 사용하려면 `.env`를 준비하고 공개 HTTPS 주소로 `APP_ORIGIN`을 변경합니다.

```bash
docker compose up --build -d
```

호스트 `127.0.0.1:3000`을 HTTPS 프록시에 연결합니다. 웹과 워커는 `status-data` 볼륨을 공유합니다. 컨테이너의 Ping 검사를 위해 워커에 `NET_RAW` 권한을 부여합니다. 웹 프로세스나 워커를 복제해서 여러 서버에 분산 배포하는 구성은 지원 범위에 포함하지 않습니다.

## 설정과 데이터

| 변수 | 용도 |
|---|---|
| `ADMIN_PASSWORD` | 초기 관리자 비밀번호. 12~1024자. 콘솔에서 변경한 후에는 DB의 비밀번호가 우선 |
| `ENCRYPTION_KEY` | 32바이트 키를 64자리 16진수로 표현 |
| `APP_ORIGIN` | 브라우저가 접근하는 origin(경로 제외). 개발 기본값 `http://localhost:5173`, 운영은 HTTPS 필수 |
| `HOST`, `PORT` | API 수신 주소·포트 |
| `DATABASE_PATH` | SQLite 파일. 기본 `./data/status.db` |
| `RETENTION_DAYS` | 검사 원시 기록 보관 기간. 기본 90일, 최소 30일 |

모니터 설정과 SMTP 인증 정보는 DB에 암호화해 저장합니다. `.env`와 데이터 볼륨을 함께 안전하게 백업하고 저장소에 커밋하지 마세요. `ENCRYPTION_KEY`를 바꾸거나 잃으면 기존 설정을 복호화할 수 없습니다. 운영 중 DB 백업은 SQLite의 backup 기능을 사용하거나 두 프로세스를 정지한 뒤 DB와 WAL 파일을 함께 보관하세요.

공개 API는 검사 주소, 인증 헤더·본문, 상세 오류와 SMTP 설정을 반환하지 않습니다. 검사 대상은 공개 인터넷 주소만 허용합니다. DNS 결과와 리다이렉트를 검사하고 연결할 IP를 고정합니다. 외부 이미지 URL을 사용하는 경우 이미지 제공자에게 방문자의 일반 브라우저 요청이 전달됩니다.

## 개발 검증

```bash
npm run typecheck
npm test
npm run build
```

브라우저 검사는 개발 서버를 종료한 뒤 실행합니다. 테스트가 API 40531번과 Vite 5174번 포트를 사용하고 별도 테스트 DB를 생성합니다.

```bash
npx playwright install chromium
npm run test:e2e
```

기존 Chromium 실행 파일을 사용하려면 `CHROMIUM_PATH` 환경 변수로 경로를 지정할 수 있습니다.

구조는 [Project_tree.md](Project_tree.md), 구현 범위는 [개발 계획](devdocs/plans/initial-implementation.md)을 참고하세요.

최초 구현의 검증 범위와 운영상 제한은 [검증 기록](devdocs/reviews/initial-validation.md)을 참고하세요.

개발 모드(`NODE_ENV=development`)에서는 `APP_ORIGIN`과 같은 프로토콜·포트의 `localhost`, `127.0.0.1`, `[::1]`에서도 관리자 로그인과 저장이 가능합니다. 운영 모드는 지정된 `APP_ORIGIN`만 허용합니다.
